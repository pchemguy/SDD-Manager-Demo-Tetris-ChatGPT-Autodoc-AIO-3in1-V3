# Milestone 8.1 — Local desktop runtime

## Result and scope

T-056 establishes the pinned secure Electron shell, T-057 produces the shared desktop renderer and hashed local asset inventory, and T-058 checks the complete capability and consumers. The Windows portable artifact is assigned to milestone 8.2; this milestone does not deliver or release a Windows package.

## Review and verification

Independent read-only review inspected the shell, origin, build, renderer entry and browser adapter contracts from release source c52b5e85aa944641491c37684f134ba1f1fcb2ab through published T-057 3be9f737ed66fecfefdb19b49efc22d0b2931502 and T-058 acceptance changes. No production correctness or security blocker was found. Independent focused origin/shell checks pass 7/7. Two test findings were corrected: URL pathname conversion now uses fileURLToPath for spaces/Windows paths, and the lifecycle test explicitly resumes and checks running state after blur pause.

Current `npm run check` passes both DOM/shared and Node-only Electron configurations; `npm run test:unit` passes 206/206. Actual assembly is exercised through the production handler: secure app-origin allowlist, hash validation, worker/schema/WASM inventory, MIME, traversal/foreign initiator/method rejection, immutable acquisition and corrupt startup failure. Native-host recorders verify scheme registration before ready, persistent session binding, sandbox/isolation/no Node/preload, navigation/popups/network/permission denial and close-to-quit.

`TETRIS_FIREFOX_SANDBOX_WORKAROUND=1 TETRIS_DESKTOP_TEST=1 TETRIS_PACKAGED_TEST=1 npm run test:e2e -- --project=firefox tests/e2e/desktop-runtime.spec.ts tests/e2e/baseline.spec.ts tests/e2e/files-json.spec.ts tests/e2e/files-sqlite.spec.ts` passes 10 cases, with two explicit exclusions: source-module composition requires authored source, and nested HTTP deployment belongs to the browser ZIP (the desktop origin deliberately serves only root manifest resources). The actual built desktop renderer, real codec worker/WASM and handler CSP run through a test-only HTTP transport. Covered: game-over/restart, settings reload/cookies/query, no renderer Node globals, synthetic blur pause/explicit resume, real JSON/SQLite download and restore, full validation/no-mutation, handled persistence rollback and SQLite failure/timeout/retry.

An existing baseline assertion initially observed extra timed soft-drop steps because its installed clock continued in real time. It now freezes time before exact-count assertions; rerun passes. The initial nested-deployment run failed for its absent browser extraction fixture; it is explicitly excluded only from desktop transport and remains enabled for browser-artifact checks.

## Environment and limits

Linux/Node 24.22.1. Managed Firefox 157.0 revision1555 was recovered from the official Microsoft archive, fully ZIP/CRC checked and safely extracted under the dedicated project cache. The documented local-trusted-page sandbox override is explicit. Chromium shell156 CDN returned195 bytes of HTML; official OCI manifest retrieval succeeded, but required config requests repeatedly timed out. Chromium reprovisioning is not claimed successful. Prior release browser evidence is retained, not relabeled as a new desktop run.

HTTP transport establishes shared renderer/CSP/file behavior; it does not establish native Electron scheme/cookie integration, OS focus delivery, native Windows launch or installation. Windows execution is unavailable on this Linux host and excluded under the central policy. Feasible artifact checks and cumulative browser checks remain milestone8.2/phase obligations.
