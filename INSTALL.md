# Install and play

## Browser application

Download `tetris-browser.zip` and `SHA256SUMS.txt` from the same release. Verify the ZIP SHA-256 against the checksum file, then extract it into an empty directory. Serve that directory over HTTP(S) using any static web server; for example, with Python installed:

```text
python -m http.server 8080 --directory PATH_TO_EXTRACTED_FOLDER
```

Open `http://localhost:8080`. A hosted static deployment needs no Python or Node.js on the player's computer. Direct `file:` opening is not supported. The project `LICENSE` and `THIRD-PARTY-NOTICES.txt` are included. Runtime JavaScript, CSS, codec worker and matching SQLite WebAssembly are bundled locally; no CDN, backend or development server is needed.

Use Left/Right to move, Down to soft drop, Up/X to rotate clockwise and Z to rotate back. Space hard drops and C holds once per lock. Clearing exactly four rows earns one penetrator bonus (maximum three); P spends one to activate a white piece until lock. It can pass through occupied cells but locks only in a non-overlapping final pose. Hold is unavailable while penetrator is active. Escape pauses/resumes. Start/Restart starts a fresh game; Pause/Start pauses or resumes. Losing window focus pauses and clears held keys. This modern browser release uses seven-bag pieces, ordered wall kicks, next/held previews and an outlined ghost. Hard drop uses the shared landing and awards actual-distance points. By default it follows the full remaining gravity-interval grounding delay; repeating a zero-distance drop does not restart it. Other platforms are scheduled later.

The Settings panel has six controls: Ghost (Hide, Dynamic or Show; default Show), Hard drop (Enabled), Next preview (Enabled), Hard drop lock (General policy), Lock policy (Full interval) and Hold (Enabled). Dynamic shows the outlined landing when any cell reaches the lower half of the board. Disabling hold retains its stored piece. Visibility and action toggles apply immediately; selected lock policies take effect on the next piece, including a hold replacement. The hint shows a pending change; the game info describes the current piece. Failed step locks on a failed downward move; Immediate hard drop locks on that action. Restart keeps these selections. Each setting initializes from a valid URL value, then its saved browser cookie, then its default. URL names are `ghost`, `hardDrop`, `nextPreview`, `hardDropLock`, `lockPolicy` and `hold`; use `true`/`false` for toggles, `hide`/`dynamic`/`show` for ghost, `general`/`immediate` for hard-drop locking, and `failed`/`interval` for the lock policy. Valid explicit URL choices, including defaults, are saved. Invalid or repeated known query values show a warning and fall back independently; unrelated parameters, fragments and cookies remain intact.

Changing a control saves that selection to a `tetris.<key>` cookie and updates its URL key without reloading or restarting play. Reload restores the per-key configuration; scores and the active game remain session-only. Cookies use the current origin and path `/`, SameSite=Lax and one-year lifetime, with Secure on HTTPS. The live selection changes only after a successful save. A failure keeps the last accepted selection and shows an error; if storage also blocks recovery, the message says that previous persistence could not be fully restored. No browser localStorage is used for settings.

The session top ten records each completed game once, sorted by score descending, UTC completion time ascending and stable ID. Restart keeps completed history; reload clears it. Choose JSON or SQLite in the Settings panel, then Save to download `tetris-save.json` or `tetris-save.sqlite`. Both contain only the top ten and six selected settings, excluding the active game, timers, board and panel state. The included `schemas/snapshot.schema.json` describes version1, with additional runtime checks for real calendar dates and unique IDs.

Restore accepts either format, detects content rather than relying on its filename, and replaces the list while preserving IDs and original timestamp spellings. All content is validated before any cookie/URL write. JSON is UTF-8 with at most one BOM. SQLite metadata, table/key structure, integrity and actual stored values are validated too. Files above 4 MiB or invalid fields/versions/duplicates are rejected; local worker processing is limited to 10 seconds. A successful Restore saves all six settings to cookies and URL before changing the live list/selections. The current game is retained and current-piece lock policies remain captured until the next piece. A reported failure leaves live data unchanged and reports any externally prevented persistence rollback honestly. File interaction pauses play; use Start or Escape explicitly to resume. Save confirms a browser download request, not an OS write beyond the browser's acknowledgement.

Chromium headless shell and Playwright-managed Firefox were tested on Linux. Native Windows execution and browser sidebar installation are not claimed for this browser-only phase. This package is a deployable static application, not a signed installer or store package.

`BUILD-INFO.json` inside the ZIP identifies its version, source commit and whether candidate source changes were uncommitted. Published release packages must report `sourceDirty: false` and match the release tag's commit.
