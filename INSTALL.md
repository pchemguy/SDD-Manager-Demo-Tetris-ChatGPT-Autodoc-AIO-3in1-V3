# Install and play

## Browser application

Download `tetris-browser.zip` and `SHA256SUMS.txt` from the same release. Verify the ZIP SHA-256 against the checksum file, then extract it into an empty directory. Serve that directory over HTTP(S) using any static web server; for example, with Python installed:

```text
python -m http.server 8080 --directory PATH_TO_EXTRACTED_FOLDER
```

Open `http://localhost:8080`. A hosted static deployment needs no Python or Node.js on the player's computer. Direct `file:` opening is not supported. The project `LICENSE` and `THIRD-PARTY-NOTICES.txt` are included. Runtime JavaScript, CSS, codec worker and matching SQLite WebAssembly are bundled locally; no CDN, backend or development server is needed.

Use Left/Right to move, Down to soft drop, Up/X to rotate clockwise and Z to rotate back. Space hard drops and C holds once per lock. Clearing exactly four rows earns one penetrator bonus (maximum three); P spends one to activate a white piece until lock. It can pass through occupied cells but locks only in a non-overlapping final pose. Hold is unavailable while penetrator is active. Escape pauses/resumes. Start/Restart starts a fresh game; Pause/Start pauses or resumes. Losing window focus pauses and clears held keys. This modern browser release uses seven-bag pieces, ordered wall kicks, next/held previews and an outlined ghost. Hard drop uses the shared landing and awards actual-distance points. By default it follows the full remaining gravity-interval grounding delay; repeating a zero-distance drop does not restart it. The same shared gameplay is available in the Windows desktop package.

At 1280 CSS pixels and above, panels appear as leaderboard, game information/controls, centered board, settings and controls/help. Three Hide/Show buttons above the bottom gameplay row independently control leaderboard, settings and help. Information and board remain available. Hiding settings hides all its file controls and removes them from keyboard/accessibility navigation; showing retains selections. These presentation choices do not become saved settings or file fields. Below 1280, essential information is above the centered board, followed by optional leaderboard/settings/help sections. The layout fits 320px with vertical scrolling and uses device-pixel Canvas backing. Start/Restart is the left gameplay button; right-hand Start resumes a paused game. Buttons return keyboard focus to the board, while form controls keep normal keyboard behavior. Status/file feedback remains accessible if settings is hidden.

The Settings panel has six controls: Ghost (Hide, Dynamic or Show; default Show), Hard drop (Enabled), Next preview (Enabled), Hard drop lock (General policy), Lock policy (Full interval) and Hold (Enabled). Dynamic shows the outlined landing when any cell reaches the lower half of the board. Disabling hold retains its stored piece. Visibility and action toggles apply immediately; selected lock policies take effect on the next piece, including a hold replacement. The settings hint shows a pending change; Controls/help describes the current piece policies. Failed step locks on a failed downward move; Immediate hard drop locks on that action. Restart keeps these selections. Each setting initializes from a valid URL value, then its saved browser cookie, then its default. URL names are `ghost`, `hardDrop`, `nextPreview`, `hardDropLock`, `lockPolicy` and `hold`; use `true`/`false` for toggles, `hide`/`dynamic`/`show` for ghost, `general`/`immediate` for hard-drop locking, and `failed`/`interval` for the lock policy. Valid explicit URL choices, including defaults, are saved. Invalid or repeated known query values show a warning and fall back independently; unrelated parameters, fragments and cookies remain intact.

Changing a control saves that selection to a `tetris.<key>` cookie and updates its URL key without reloading or restarting play. Reload restores the per-key configuration; scores and the active game remain session-only. Cookies use the current origin and path `/`, SameSite=Lax and one-year lifetime, with Secure on HTTPS. The live selection changes only after a successful save. A failure keeps the last accepted selection and shows an error; if storage also blocks recovery, the message says that previous persistence could not be fully restored. No browser localStorage is used for settings.

The session top ten records each completed game once, sorted by score descending, UTC completion time ascending and stable ID. Restart keeps completed history; reload clears it. Choose JSON or SQLite in the Settings panel, then Save to download `tetris-save.json` or `tetris-save.sqlite`. Both contain only the top ten and six selected settings, excluding the active game, timers, board and panel state. The included `schemas/snapshot.schema.json` describes version1, with additional runtime checks for real calendar dates and unique IDs.

Restore accepts either format, detects content rather than relying on its filename, and replaces the list while preserving IDs and original timestamp spellings. All content is validated before any cookie/URL write. JSON is UTF-8 with at most one BOM. SQLite metadata, table/key structure, integrity and actual stored values are validated too. Files above 4 MiB or invalid fields/versions/duplicates are rejected; local worker processing is limited to 10 seconds. A successful Restore saves all six settings to cookies and URL before changing the live list/selections. The current game is retained and current-piece lock policies remain captured until the next piece. A reported failure leaves live data unchanged and reports any externally prevented persistence rollback honestly. File interaction pauses play; use the right-hand Start or Escape explicitly to resume. Save confirms a browser download request, not an OS write beyond the browser's acknowledgement.

Chromium headless shell and Playwright-managed Firefox were tested on Linux. Native Windows execution and browser sidebar installation are not claimed by these browser checks. This package is a deployable static application, not a signed installer or store package.

`BUILD-INFO.json` inside the ZIP identifies its version, source commit and whether candidate source changes were uncommitted. Published release packages must report `sourceDirty: false` and match the release tag's commit.

## Windows desktop — unsigned portable development package

Download `tetris-windows-x64.zip`, `INSTALL.md` and `SHA256SUMS.txt` from the same release. Verify the ZIP hash, extract the **entire** archive into an empty writable directory and launch `Tetris.exe`. Keep its DLLs, locale files and `resources` directory together. No Node.js installation, browser, local server or backend is required. Windows x64 is the package target; native Windows launch/installation was not tested on the Linux build host.

This is an **unsigned development ZIP**, not a signed installer, Microsoft Store package or browser-store distribution. Windows may display publisher/reputation warnings. The executable retains Electron's pristine runtime metadata; application version/source are in `BUILD-INFO.json` and `resources/app/package.json`. Do not confuse Electron's version with the game version.

The desktop window uses the shared wide/compact layout and keyboard controls above. It serves only bundled assets from `app://tetris/` on a persistent application session, without Node/preload access in the renderer. Settings use that app's cookies and URL independently of browser settings. Edits and Restore update the app URL; subsequent launches restore saved cookie choices. Scores and active gameplay remain session-only; closing the window ends that session. Save/Restore use the normal Chromium download/file-picker UI and pause play. Resume explicitly using the right-hand Start or Escape. Closing the window exits the application.

The ZIP includes Electron's `LICENSE` and `LICENSES.chromium.html` at its root, and project/license notices in `resources/app/`. Cross-host verification checks the pristine runtime hashes, AMD64 executable metadata, complete local assets and extracted shared renderer. Those checks establish package integrity and shared behavior; they are not native Windows execution evidence. Chromium and Firefox sidebar development packages remain scheduled for the final delivery phase.

## Chromium sidebar — unpacked development extension

Use `tetris-chromium.zip` from a release that includes it. Verify its checksum, extract the whole archive into a stable empty directory, open `chrome://extensions` (or the Chromium browser's equivalent), enable Developer mode, choose **Load unpacked**, and select the directory containing `manifest.json`. Pin the extension and click its action to open Tetris, or select it from the browser's side-panel menu. Chromium116 or newer is required. Keep the extracted directory in place. Updating an unpacked extension may end its session; use manual Save beforehand.

This is an unsigned development extension, not a Chrome Web Store distribution. No Node.js installation, development server or backend is required. Scripts, CSS, icons, schema, validators and SQLite WebAssembly are bundled. Permissions are only `storage` and `sidePanel`; no host-page content script or download permission is requested. The extension does not read or change the active web page's URL/cookies.

Sidebar layout is always compact and resizable: game information and board followed by collapsible leaderboard, settings and help. The same keyboard actions and two gameplay buttons apply. Settings persist in extension-local storage instead of cookies/query parameters. Another window reads saved choices the next time it opens Tetris; games do not synchronize across windows.

Game state and the session top ten are scoped to the browser window in extension session storage. Closing/reopening the sidebar restores the last acknowledged state **paused**, with its remaining timers; resume explicitly. Closing the browser window or restarting the browser ends its game/results history. The background coordinates storage only and never advances gameplay while the panel is closed. Storage failure pauses play and reports that the last unacknowledged transition may not recover; reopen to resume from the last acknowledged checkpoint. A corrupt checkpoint is discarded with a warning while valid persistent settings remain available.

Save and Restore use the ordinary browser download/file picker and the same validated JSON/SQLite content described above. Restore commits extension-local settings instead of cookies/URL. Files contain settings and top-ten results only. Keep a manual file for transfer beyond the browser session. A hidden settings section also hides Save/Restore.

Package extraction, strict local-resource/CSP checks, shared runtime under the packaged CSP and adapter/background recorders are verified on the Linux build host. Full Chromium native sidebar installation/action/open-close behavior was unavailable because the isolated full browser could not create its required UNIX socket; those native integration checks remain unverified. Headless shared-page checks do not claim native extension installation.
